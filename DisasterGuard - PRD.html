Product Requirements Document (PRD)

DisasterGuard — Real-Time Disaster Awareness & Safe Navigation MVP

Version: 1.0 (Hackathon MVP) Owner: [Your Name / Team Name] Date: September 2026

1. Problem Statement

People often have no simple way to check, at a glance, whether their current location or an upcoming trip route is near an active disaster (earthquake, flood, or forest fire). Existing tools are either too specialized (single-hazard government dashboards) or too generic (regular maps with no hazard awareness). There is no lightweight, map-first tool that combines live disaster data with route-level risk checking.

2. Goal

Build a web app that lets a user, in under 30 seconds:

  1. See active earthquakes, floods, and forest fires near their current location on a map.
  2. Enter a destination and immediately know whether their route passes through a disaster zone — and get a safer alternative if one exists.

3. Target Users

  • General public checking local disaster risk before traveling
  • Hackathon judges/demo viewers evaluating a live, working prototype
  • (Future) Disaster-response coordinators, local authorities — out of scope for MVP

4. Success Criteria (MVP Demo)

  • Map loads with user's live location and at least earthquake + fire layers populated from real free APIs
  • User can toggle each disaster layer independently
  • User can search a destination and get a route
  • If the route crosses a hazard zone, a clear warning is shown and a safer route is offered when possible
  • Demo is reliable even without a live disaster occurring nearby, via the Admin Demo panel
  • Entire flow (open app → see disasters → get warned on a bad route → see safe route) is demoable in under 2 minutes

  • Custom-built routing/navigation engine (relies on ORS)
  • Multi-language support
  • Push notifications (browser-tab only, not native push)

6. Feature Requirements

6.1 Interactive GIS Map

  • Base map: OpenStreetMap tiles via Leaflet/react-leaflet
  • User location: via navigator.geolocation; requires HTTPS or localhost
  • Layers:
    • Earthquake — red pulsing marker, radius/intensity scaled by magnitude
    • Forest Fire — orange marker, buffered circle scaled by confidence
    • Flood — blue translucent polygon (mock data; no reliable free real-time source exists)
  • Marker interaction: clicking opens a detail card with type, location, detected/reported time, severity/confidence (if available), source, last-updated timestamp
  • Data failure handling: if any live source fails or times out, fall back to a small local mock dataset for that layer and visibly flag it as cached/demo data — never show a silently blank layer

6.2 Disaster Filters

  • Toggle chips: All / Earthquake / Flood / Forest Fire
  • Toggling hides/shows the corresponding map layer group instantly (client-side only)

6.3 Location Search

  • Free-text search box using Nominatim (OSM) geocoding, no API key required
  • Selecting a result recenters/pans the map to that location

6.4 Safe Navigation

  • Input: current location (auto) → destination (search/autocomplete)
  • Routing: OpenRouteService (ORS) Directions API, free tier
  • Hazard check: convert route line and all active disaster zones to GeoJSON; use turf.js (booleanIntersects / lineIntersect) to check for overlap
  • If intersecting:
    • Show a named warning, e.g. "⚠️ Warning: This route passes through a flood-affected area"
    • Re-request route from ORS using avoid_polygons set to the hazard geometry
    • If no valid avoidance route exists, show: "No safer alternative route found — proceed with caution"
  • If clear: show "✅ Route looks clear" and render the route normally

6.5 Alert Panel

  • Bottom sheet, collapsed by default (peek handle + count badge)
  • Lists all currently active disasters (real + demo-injected), sorted nearest-to-user first
  • Each entry: icon, type, severity/magnitude, distance, detected time, source badge
  • Tapping an entry pans the map to it and opens its detail card

6.6 Admin / Demo Panel

  • Accessible via a "⚙️ Demo Mode" toggle (no real authentication needed for MVP)
  • Form to manually inject a disaster: type, coordinates (or click-to-place on map), severity/confidence, note
  • Injected disasters behave identically to real data: appear on map, in alert panel, in detail cards, and are checked against routes — tagged with source "Demo/Manual" to stay distinguishable from real data
  • "Clear all demo disasters" reset button
  • Purpose: guarantees a reliable live demo of the warning + reroute flow regardless of whether a real disaster is occurring nearby at demo time

6.7 Real-Time Alert Notification

  • Frontend polls all disaster sources (real + demo) every ~30 seconds
  • Diffs against previously seen disaster IDs; any new disaster within a configurable radius (default 20km) of the user triggers:
    • A toast notification with type, distance, and a "View" action
    • A short (1–2s) alert sound, respecting browser autoplay policy (plays only after first user interaction; otherwise shows a "tap to enable sound" hint)
  • Same mechanism fires instantly when a disaster is injected via the Admin panel, enabling an on-demand live demo of the alert

7. Non-Functional Requirements

  • Reliability over completeness: every external data source must have a local mock fallback; a failed API call must never break the map or crash the app
  • Performance: initial map + first layer paint within ~3 seconds on a typical connection
  • Responsiveness: mobile-first layout, usable on a phone screen and scales to desktop
  • Transparency: every piece of disaster data displays its source and last-updated time; simulated/demo data is never presented as if it were live/real

8. Technical Architecture

Layer Choice Notes
Frontend React + react-leaflet Component-based, mobile-first
Backend Node.js + Express (minimal) Only proxies calls needing hidden API keys (FIRMS, ORS)
Map tiles OpenStreetMap Free, no key
Earthquake data USGS Earthquake API Free, no key, GeoJSON
Fire data NASA FIRMS Free key required, point data
Flood data Mock GeoJSON polygons No reliable free real-time source exists
Geocoding Nominatim (OSM) Free, no key
Routing OpenRouteService (ORS) Free tier, supports avoid_polygons
Geometry ops turf.js Buffering, intersection checks
Database None (in-memory only) No persistence needed for MVP

9. User Flow

Open app → Map loads with GPS location → Disaster layers fetched & displayed
   → User filters layers (optional) → User searches destination
   → Route generated → Route checked against hazard zones
       → Clear → show route
       → At risk → show warning → attempt safer route → show alternative
   → Alert panel shows nearby active disasters, updated in real time
   → (Demo) Admin panel can inject a disaster on-the-fly to trigger the above flow reliably

10. Risks & Mitigations

Risk Mitigation
No free real-time flood API exists Use clearly-labeled mock/simulated flood zones
Live API downtime/rate limits during demo Local mock fallback dataset for every layer
No real disaster near demo location at demo time Admin/Demo panel to inject a controlled disaster
ORS free-tier rate limits Client-side caching of recent route requests; OSRM as backup routing option
Browser blocks autoplay sound Require one user interaction before enabling alert sound; show hint otherwise

  2. Wire live USGS + FIRMS layers
  3. Add mock flood layer + full detail cards with source/timestamp
